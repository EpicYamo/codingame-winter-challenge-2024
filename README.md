# CodinGame Winter Challenge 2024 — Pathfinder for Protein

A bot for the CodinGame Winter Challenge 2024, written in plain C with no
libraries beyond libc.

> Built by **Arda Aycan**. It was the first bot I ever wrote, roughly three
> months after I started studying software engineering.

The challenge puts two organisms on a grid. Each turn you see every organ on
the board and the proteins lying around, and you answer with a list of actions:
grow an organ, build a harvester or a sporer, or attack.

## How the bot plays

Each turn it:

1. **Parses the board** into a list of organs: id, root id, owner, parent, grid
   position, type (`ROOT`, `BASIC`, `TENTACLE`, `HARVESTER`, `SPORER`, `A`–`D`),
   direction and protein value.
2. **Indexes the proteins** on the map and remembers which ones are already
   being harvested.
3. **Picks a target** — the nearest protein of the type it needs — and grows the
   organism one cell at a time towards it, avoiding walls and its own organs.
4. **Builds harvesters** when a protein is reachable and no existing harvester
   already covers that type.
5. **Prioritises by need**: protein A first (it is the one required to attack),
   then C, D and B, switching to an aggressive line when the opponent is close.
6. **Attacks** with tentacles when A is available, and keeps a move checker so
   the same organ is not ordered twice in one turn.

The final version is about 1,700 lines. It is deliberately written in C rather
than with a graph library: every structure (organ list, protein list, grid
layers, move list) is plain arrays and pointers.

## Layout

```
Main Project/
  pathfinder.c                 the current bot
  version 1/ … version 4.5/    every iteration, kept in order
  version 5 never completed/   the rewrite that ran out of time
  *.png                        board and pathfinding screenshots
Tutorial Part/                 solutions for the tutorial bosses
Codingame PDF.pdf              the challenge statement
```

The versions are not decoration: the earlier ones show which ideas were tried
and dropped (nearest-protein only, full pathfinding, aggressive switching), and
the unfinished version 5 is kept because hiding it would misrepresent the work.

## Build and run

The bot reads from stdin and writes to stdout, exactly as the CodinGame runner
expects:

```bash
gcc -O2 -std=c99 -Wall -Wextra -o pathfinder "Main Project/pathfinder.c"
./pathfinder < input.txt
```

There is no local harness in the repository: the input format is generated by
CodinGame (`width height`, `my_material opponent_material`, then the protein
list and the organ list). The tutorial programs in `Tutorial Part/` are
self-contained and can be compiled the same way.

## Notes

- Plain C99, no external libraries.
- The bot never invents board state: every decision is made from the current
  turn's input only.
- This is a learning project, not a top-ranked solution. It is published as it
  was written.
